# ADR-018: Chat UX Layer & Agent Bridging

## Context
Sprint 3B aims to provide a conversational IDE interface while maintaining strict architectural boundaries. The existing agent runner (`agent-core`) and VS Code `ide-adapter` provided a minimal command-based trigger. We needed to introduce a persistent `WebviewView` for chat interaction without corrupting the core loop or duplicating state management.

## Decisions

1. **Webview-to-Host Protocol over Scraping**
   We explicitly define typed Webview-to-Host messages (`chat-protocol.ts`) instead of reading from `OutputChannel`. This ensures structured state management (modes, history, confirmations) and eliminates brittle text parsing.

2. **ChatController as the Single UI Source of Truth**
   A new `ChatController` handles the view's state (`WebviewState`). It accepts user inputs, manages the session history, and forwards requests to the existing `AgentSessionBridge`. 

3. **Continuity via Instruction Augmentation**
   To avoid modifying the complex `ContextCompiler` in `agent-core` (which already efficiently manages tokens for project state), `ChatController` aggregates recent chat history (capped at 1600 tokens) and formats it as `[Recent Conversation Context]` into the `instruction` string passed to the `AgentSessionBridge`. This cleanly satisfies token budgets while keeping the core agnostic to the UI format.

4. **In-Chat Confirmations**
   `IdeHost.requestConfirmation` is modified to delegate to `ChatController`. The UI displays explicit inline confirmation cards and handles `APPROVE`/`REJECT` flows. Once a user responds, the UI disables subsequent responses, preventing double approvals.

5. **Strict Security**
   The HTML is constructed entirely offline with no remote scripts or assets. A strict Content Security Policy (CSP) with a generated nonce is enforced. No `innerHTML` is used for rendering user input.

## Consequences
- The core loop is isolated and unaware of VS Code view complexities.
- Conversation history is naturally bounded and gracefully integrated into existing pipelines.
- All 35+ Chat UX integration tests pass synchronously without real model inference dependencies.
