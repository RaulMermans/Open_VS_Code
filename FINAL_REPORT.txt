SECTION 2 — CORE INVARIANTS & ARCHITECTURAL PRINCIPLES
================================================================================

1. Non-Authoritative Evaluation:
   - Evaluators advise and recommend directives, but possess zero execution or write authority.
   - Evaluation results cannot auto-approve mutations, execute shell commands, alter permissions,
     or bypass security gates.
   - An evaluation score of 1.0 or CONTINUE grants NO permission.
   - All mutations remain gated by MutationEngine and human confirmation.
   - All processes remain gated by VerificationEngine and allowlisted executables.

2. Multi-Level Tiered Evaluation Hierarchy:
   - Level 0 (L0): Purely deterministic rule-based checks (< 1ms latency, 0 token cost).
   - Level 1 (L1): Heuristic multi-dimensional scoring (progress, completion confidence,
     verification coverage, plan adherence, execution efficiency, logical consistency,
     safety authority) with deterministic action cycle detection and loop penalties.
   - Level 2 (L2): Selective critic invocation for repeated failures (>= 2) or ambiguous states.
     Racing timeout fallback (default 5000ms) guarantees non-blocking fallback to L1 heuristic.

3. Four Discrete Execution Checkpoints:
   - MUTATION_RESULT: Evaluates immediately after code mutation application.
   - TOOL_FAILURE: Evaluates upon tool rejection, denial, or runtime failure.
   - VERIFICATION_RESULT: Evaluates after verification execution (test, typecheck, lint).
   - BEFORE_COMPLETION: Evaluates when the agent signals final answer completion.

4. Adaptive Control Loop & 8 Concrete Decisions:
   - Directives: CONTINUE, SCHEDULE_VERIFICATION, INJECT_REVISION, TRIGGER_REPLAN,
     TERMINATE_RUN, PAUSE_HUMAN, RECOMMEND_MODEL / CHANGE_MODEL, REQUEST_MORE_CONTEXT.
   - CHANGE_MODEL injects narrow ModelRouteHint (avoidDeploymentId, preferredCapabilities,
     preferredDeploymentId, reasonCode) with 1-turn bounded lifetime into ModelRouter without
     cloud fallback or provider reconstruction.
   - REQUEST_MORE_CONTEXT expands context boundedly (MAX_CONSECUTIVE_CONTEXT_REQUESTS = 2), updates
     evidence with incremented evidenceVersion, triggers explicit re-evaluation, and consumes second directive.
   - AgentRunner supports configurable `runtimeEvals?: boolean` and `adaptiveInterventions?: boolean`
     (both defaulting to true), ensuring scripted benchmarks run cleanly while retaining evaluation metrics.

5. Universal Post-Verification Causality & Outcome Linking:
   - All paths scheduling verification (MUTATION_RESULT, BEFORE_COMPLETION, or generic directives)
     execute verification, run VERIFICATION_RESULT checkpoint eval, record outcome in RuntimeEvalLedger,
     and consume the corrective directive (REVISE, REPLAN, ASK_HUMAN, STOP, CONTINUE).
   - RuntimeEvalLedger links outcomes (RESOLVED, IMPROVED, UNCHANGED, DEGRADED) back to originating eval
     and intervention IDs across model changes, context requests, and verification cycles.

6. Bounded Evidence & Secret Hygiene:
   - Collections bounded to prevent unbounded memory growth (actions, outcomes, mutations, verifications,
     security signals, route signals, unresolved failures all capped at 10-20 items).
   - Automatic regex secret redaction scrubs API keys (`sk-[a-zA-Z0-9_-]{8,}`), bearer tokens,
     and private keys into `[REDACTED_SECRET]`.
