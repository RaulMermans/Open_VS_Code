SECTION 7 — BOUNDED PREFIX BUFFER POLICY
================================================================================

Per-stream budget:  maxOutputBytes (default 16,384 bytes)
Buffer type:        PREFIX (first N bytes retained, not ring/circular)
Overflow behavior:  Chunk sliced to remaining capacity by truncateUtf8Buffer;
                    further chunks silently discarded
Truncation flag:    stdoutTruncated / stderrTruncated = true
Multi-byte safety:  truncateUtf8Buffer walks back from byte limit to exclude
                    trailing UTF-8 continuation bytes (0x80–0xBF) and
                    incomplete leading bytes; no \uFFFD produced

================================================================================
SECTION 8 — REGISTRY BOUNDING POLICY
================================================================================

maxReviews (default 50):
  Enforced before each registerPreparedCommand call.
  Evicts the oldest Map entry whose status is in the completed set.
  Never evicts WAITING_APPROVAL or RUNNING entries.

maxTotalRetainedBytes (default 1,048,576 = 1MB):
  Enforced after each appendOutput and recordCompletion call.
  Measured as sum of Buffer.byteLength(stdout) + Buffer.byteLength(stderr)
  across all retained entries.
  Evicts the oldest completed entry until within budget.

================================================================================
SECTION 9 — PROCESS GROUP CLEANUP DESIGN
================================================================================

Spawn:   spawn(executable, args, { shell: false, detached: true, cwd })
         child.unref() allows node process to exit independently

Kill:    On cancellation (AbortSignal) or timeout:
           process.kill(-child.pid, "SIGTERM")   // targets process GROUP
           [grace period]
           process.kill(-child.pid, "SIGKILL")   // hard kill if still alive

Scope:   All processes sharing the process group (parent + all descendants)
         are terminated. No orphaned background tasks remain.

SECTION 10 — UTF-8 DECODER LIFECYCLE
================================================================================

VerificationEngine:
  stdoutDecoder = new StringDecoder("utf-8")  // created before spawn
  stderrDecoder = new StringDecoder("utf-8")  // created before spawn
  On data chunk: decoder.write(buffer) → string delivered to onOutput
  On stream end: decoder.end() → flush any trailing incomplete sequence

TerminalReviewController:
  stdoutDecoders: Map<executionId, StringDecoder>  // lazy-created on first chunk
  stderrDecoders: Map<executionId, StringDecoder>  // lazy-created on first chunk
  On recordCompletion: decoder.end() flushes; decoders deleted from maps

SECTION 18 — KNOWN LIMITATIONS (DOCUMENTED, NOT DEFECTS)
================================================================================

1. Prefix buffer (first 16KB) — very long-running commands producing >16KB output
   will have their later output silently dropped. The truncation flags and
   configurable limit mitigate this. A full streaming transport (WebSocket / IPC)
   would be needed for unlimited output; that is a future sprint scope.

2. SIGTERM + SIGKILL on Linux/macOS only — Windows requires taskkill /T /F /PID.
   Windows process group cleanup is deferred to a future sprint.

3. npm lifecycle header lines appear as the first verification.output event.
   Consumers should filter or display all output lines (not just the first).
   Tests now correctly search for content-bearing chunks rather than the first event.

SECTION 20 — TOOLCALLS PLACEMENT CORRECTION (TECHNICAL NOTE)
================================================================================

During Sprint 3D.1 development the ModelResponse contract was validated:

  ModelResponse = { model: string; message: ModelMessage; toolCalls?: ToolCall[] }

toolCalls is a top-level property on ModelResponse, NOT on ModelMessage.
The corrected placement in scenarios 51 and 52 was required for AgentRunner
to recognize tool calls and pause for confirmation. Placing toolCalls inside
message caused AgentRunner to see 0 tool calls and immediately complete,
preventing the PAUSED state and bypassing the subprocess.

SECTION 21 — EVICTION ORDER CORRECTNESS
================================================================================

JavaScript Maps iterate in insertion order. The enforceReviewCountBudget and
enforceTotalRetainedBytesBudget methods iterate from the oldest (first inserted)
entry and evict the first completed entry found.

This means the oldest completed entry is evicted first — preserving recent
execution history at the cost of older history. Active entries at any
insertion position are skipped.

Test scenario 50 verifies this correctly: R1 (older, SUCCEEDED) is evicted
when R2 (newer, SUCCEEDED) pushes total bytes over the limit.

Correctness note: appendOutput on a SUCCEEDED entry is rejected by the guard
on lines 188-190 of terminal-review-controller.ts. Tests must call setStatus
to RUNNING before appendOutput, then setStatus to SUCCEEDED after. Scenarios
that set SUCCEEDED before appending will have zero bytes and no eviction trigger.
