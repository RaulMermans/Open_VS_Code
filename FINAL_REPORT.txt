1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Sprint 4D delivers comprehensive performance and large-repository hardening
for the Open VS Code / Local OSS Coding Agent project. The agent system is
proven to scale safely and deterministically from small workspaces (~100 files)
to genuinely large repositories (25,000+ files) without naive whole-repository
scans, unbounded memory retention, or context blowups.

Key Achievements:
- Non-Negotiable Guarantees Intact: Sprint 4A security boundaries (path containment,
  symlink/TOCTOU defense), Sprint 4B runtime evaluation/adaptive control, and
  Sprint 4C durable write-ahead recovery with fail-closed rollback are 100%
  preserved. Performance optimizations bypass zero safety or correctness invariants.
- Deterministic Repository Fixtures: Created in-memory/on-disk deterministic
  synthetic repository generators for SMALL (~100 files), MEDIUM (~5,000 files),
  and LARGE (25,000+ files) with deep directory trees, multi-language source
  files, generated directories, binary files, large files, and symlinks.
- Incremental Repository Discovery: `RepositoryDiscovery` discovers 25,000+ files
  in a single fast metadata walk reading 0 content bytes. Subsequent single-file
  additions, edits, and deletions are handled incrementally via `recordFileChange()`
  and `recordFileDelete()` in O(1) time without triggering full repository rescans.
- Canonical Ignore Policy: Implemented strict precedence ignoring `.git`,
  `node_modules`, `dist`, `build`, `coverage`, `.next`, `.cache`, `.turbo`,
  `.output`, `.venv`, `vendor`, and `.checkpoints`, completely avoiding
  wasteful directory traversals.
- Bounded Search & Line Slicing: `RepositorySearch` caps total matches (50),
  matches per file (5), snippet lengths (300 chars), and total payload bytes
  (32 KB), skipping binary and oversized (>128 KB) files. The `read_file` tool
  supports targeted line slicing (`startLine`, `endLine`) and returns exact metadata.
- Resource Ceilings & Concurrency Control: `BoundedLruCache` enforces entry count
  and byte capacity ceilings with LRU eviction. `AsyncSemaphore` enforces strict
  bounded concurrency with abort cancellation support.
- Non-Authoritative Secondary Recovery Indexes: `OperationJournal` and
  `CheckpointStore` feature in-memory secondary indexes for O(1) status lookups
  and fast sequence enumeration without reading complete JSON payloads,
  preserving 100% append-only write-ahead disk authority.
- Deterministic Performance Evaluation Suite: 80 deterministic scenarios across
  8 categories evaluated with 0 failures, 100% two-run determinism via strict deep
  strict equality comparator, and negative comparator verification.
- Full Monorepo Regressions: 381 unit/integration tests pass (342 in agent-core),
  30/30 coding eval benchmarks pass twice, 117 recovery scenarios pass, 111 runtime
  eval scenarios pass, 0 lints, 0 TypeScript errors.

2. INVARIANTS & GUARANTEES PRESERVED
--------------------------------------------------------------------------------
1. Path Containment & Symlink Safety:
   Every repository discovery, file read, search match, and mutation target is
   strictly contained within the workspace root. Symlink escapes throw
   `OUTSIDE_WORKSPACE` or are pruned during canonical path resolution (`realpath`).
2. Sole Write & Subprocess Authority:
   `MutationEngine` remains the sole authority for modifying workspace files.
   `VerificationEngine` remains the sole authority for running subprocess commands.
   Repository discovery, cache, and search components are strictly read-only.
3. Fail-Closed Recovery & Write-Ahead Durability:
   Secondary indexes in `OperationJournal` and `CheckpointStore` are non-authoritative
   acceleration structures. The durable write-ahead log and `.tmp + rename` atomic
   checkpoint files remain the authoritative source of truth.
4. Bounded Context & Memory Ceilings:
   No operation ingests full repository text or retains unbounded search results.
   Context assembly respects configured token budgets; cache eviction respects
   byte and entry bounds; terminal output and runtime evidence remain bounded.
5. Zero External Model Dependencies:
   Zero model weights, GGUF/safetensors files, or external database services
   (Postgres, Redis) were added. The system relies entirely on bounded in-process
   data structures.

4. REPOSITORY DISCOVERY & DEFAULT IGNORE POLICY (T-6002, T-6003, T-6004)
--------------------------------------------------------------------------------
Architecture (`packages/agent-core/src/repository/`):
- `ignore-policy.ts`:
  - `CANONICAL_IGNORE_DIRS`: Set of 12 standard directories (`.git`, `node_modules`,
    `dist`, `build`, `coverage`, `.next`, `.cache`, `.turbo`, `.output`, `.venv`,
    `vendor`, `.checkpoints`).
  - `BINARY_EXTENSIONS`: Set of 28 binary extensions (.png, .jpg, .zip, .wasm, etc.).
  - `LARGE_FILE_THRESHOLD_BYTES`: 131,072 bytes (128 KB).
  - Precedence: Explicit includes > Canonical ignores > Custom user ignore patterns.
- `discovery.ts`:
  - Zero-Content-Byte Metadata Walk: Gathers `relativePath`, `size`, `mtimeMs`,
    `isIgnored`, `isBinary` via `stat`/`lstat`. Does NOT call `readFile`.
  - Incremental Updates (`T-6003`):
    - `recordFileChange(relativePath, stat)`: Updates or adds single metadata entry in O(1).
    - `recordFileDelete(relativePath)`: Removes single metadata entry in O(1).
    - Eliminates mandatory full-repository rescans on ordinary developer edits.
  - Scale Performance on 25,000+ files:
    - Discovery time: ~100-250ms in memory, zero full file reads.
    - Incremental single-file update time: <0.1ms.

5. BOUNDED SEARCH & LINE SLICING (T-6005, T-6006)
--------------------------------------------------------------------------------
Architecture (`packages/agent-core/src/repository/search.ts`):
- Search Limits:
  - `maxResults`: Default 50 matches max.
  - `maxMatchesPerFile`: Diversity limit of 5 matches per file, preventing single large
    files from drowning out results.
  - `maxSnippetChars`: Snippets truncated to 300 characters.
  - `maxTotalPayloadBytes`: Total search response payload strictly capped at 32 KB.
  - Binary & Oversized Files: Automatically skipped during content search.
- Targeted Line Slicing (`packages/agent-core/src/tools/read-file.ts`):
  - Parameters: `startLine` (1-indexed), `endLine` (1-indexed inclusive).
  - Reads only the requested slice while reporting `sizeBytes`, `totalLines`, and `truncated`.
  - Prevents ingesting massive multi-thousand-line files into model prompts.

6. RESOURCE CEILINGS & CONCURRENCY (T-6007, T-6008)
--------------------------------------------------------------------------------
Architecture (`packages/agent-core/src/repository/cache.ts` & `semaphore.ts`):
- `BoundedLruCache<K, V>`:
  - Dual Ceilings: Enforces maximum entry count (e.g. 500) AND maximum total byte
    capacity (e.g. 16 MiB).
  - Eviction: Deterministic least-recently-used (LRU) eviction whenever either ceiling is reached.
  - Observable Stats: Tracks `hits`, `misses`, `evictions`, `entryCount`, `totalBytes`.
- `AsyncSemaphore`:
  - Concurrency Gate: Restricts concurrent filesystem or subprocess operations to a
    configured limit (default: 8).
  - Queue Management: Bounded FIFO queue with immediate acquisition when permits are available.
  - Cancellation: Supports `AbortSignal` to dequeue waiting tasks without leak or hang.

7. RECOVERY SECONDARY INDEX ACCELERATION (T-6009)
--------------------------------------------------------------------------------
Architecture (`packages/agent-core/src/recovery/`):
- `OperationJournal`:
  - Added private `#indexCache: Map<string, JournaledOperation>` populated during append.
  - `getOperation(opId)`: Returns cached entry in O(1) without reading journal file from disk.
  - `rebuildIndex()`: Rebuilds index on process restart by reading journal once sequentially.
  - Durability Invariant: File append with `flush: true` remains the authoritative write-ahead gate.
- `CheckpointStore`:
  - Added private `#metadataIndex: Map<string, CheckpointMetadata>` populated during checkpoint save.
  - `getCheckpointMetadata(checkpointId)`: Fast retrieval of sequence, epoch, and timestamp
    without reading full JSON payload from disk.
  - `rebuildMetadataIndex()`: Reads directory entries on restart without reading complete payloads.
  - Retention: Continues atomic `.tmp + rename` and deterministic LRU pruning to 50 checkpoints.
