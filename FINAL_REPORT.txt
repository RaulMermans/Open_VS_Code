SECTION 2 — CORE INVARIANTS & ARCHITECTURAL PRINCIPLES
================================================================================

1. Observed State Dictates Recovery:
   - Recovery never assumes or guesses in-flight execution results.
   - Mutations are reconciled to RECONCILED_APPLIED only when disk files exist with the exact
     expected postcondition SHA-256 hash. Write replay count is strictly 0 (never double-write).
   - Mutations are reconciled to RECONCILED_NOT_APPLIED if disk files match precondition SHA-256 hash.
   - Any hash discrepancy where disk differs from both precondition and postcondition is classified as
     AMBIGUOUS / BLOCKED_DIVERGENCE, halting automated recovery and requiring ASK_HUMAN disposition.
   - In-flight verifications interrupted mid-flight cannot be assumed to have succeeded; they are
     reconciled to INTERRUPTED, requiring REVERIFY disposition.
   - Completed verifications are durably preserved without re-running.

2. Fail-Closed Durability Gates:
   - Pre-mutation and pre-verification journal/checkpoint persistence errors immediately halt execution
     before side effects occur on the filesystem or external processes, failing closed with INTERNAL_ERROR
     (DURABILITY_UNAVAILABLE).
   - Post-mutation persistence failure records error, halts execution, but does not replay writes or
     attempt unverified rollbacks.
   - Task completion checkpoint failure transitions task status to FAILED with INTERNAL_ERROR instead of
     reporting durable completion.
   - RepairOrchestrator propagates CheckpointCoordinator to all sub-runners, guaranteeing full operation
     journaling for automated repairs.

3. Strict Authority Separation:
   - In strict alignment with ADR-023 §10 and ADR-024 §1, RecoveryController is strictly diagnostic/planning.
   - RecoveryController never executes filesystem writes, spawns shell processes, or grants permissions.
   - All rollback operations evaluate candidates and execute reverse mutations exclusively
     through the authoritative MutationEngine under existing workspace containment boundaries.
   - All verifications execute exclusively through VerificationEngine under security boundaries.

4. Process Epoch Protection Across Restarts:
   - Every process lifecycle generates a unique processEpochId via crypto.randomUUID().
   - Checkpoints persist the active processEpochId.
   - On restart (when processEpochId !== checkpoint.processEpochId), any pending approval,
     confirmation token, or unexecuted approved mutation is strictly invalidated.
   - RecoveryPlan emits required approval NEW_EPOCH_AUTHORITY_REQUIRED and disposition RECONFIRM.
   - Stale approval tokens cannot be silently reused or replayed across process restarts.

5. Write-Ahead Operation Journal:
   - All stateful mutations, verifications, and external calls write an intent record to an append-only
     JSONL journal before touching the filesystem or invoking processes.
   - Deterministic idempotency key: SHA-256(runId:evidenceVersion:kind:authorityId:intentHash).
   - Deduplication: Reading operations for a run deduplicates entries to their latest lifecycle status.
   - Retry lineage: Retried operations generate fresh execution identities while tracking replacesOperationId.

6. Atomic Checkpoint Store:
   - Checkpoints written to temporary files (.tmp.<random>) and atomically renamed.
   - SHA-256 integrity checksum over canonical JSON payload. Corrupt or truncated files fail verification.
   - Schema versioning with fail-closed behavior for unsupported future versions.
   - Bounded retention: CheckpointStore automatically prunes history to retain at most 50 checkpoints per run.
   - Atomic HEAD pointer file tracks the latest sequence.

7. Bounded Recovery Artifact Store:
   - Original file preimages captured prior to modify/delete mutations.
   - Strict size bounds: single file maximum 8 MiB, run maximum 64 MiB. Exceeding bounds fails closed.
   - Zero telemetry leaks: Preimages are stored exclusively in local recovery directory and are strictly
     prevented from entering model prompts, analytics, or telemetry payloads.

8. Safe Rollback Semantics:
   - CREATE rollback: Deletes created file if current disk hash matches created postcondition hash.
   - MODIFY rollback: Retrieves captured preimage and applies reverse patch via MutationEngine.
   - DELETE rollback: Retrieves captured preimage and recreates deleted file via MutationEngine.
   - TOCTOU protection: Immediate re-observation of target path prior to rollback write; files modified
     outside the agent turn are classified as DIVERGED and rollback is safely aborted.

9. Fail-Closed Path Safety & Symlink Protection:
   - assertSafeStoragePath() canonicalizes both storage root and target paths across symlinked temporary
     directories (such as macOS /var -> /private/var).
   - Traversal escapes and symlinks escaping workspace storage boundaries are rejected with SYMLINK_ESCAPE.
